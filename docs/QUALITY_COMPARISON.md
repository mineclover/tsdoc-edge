# 품질 비교: 수동 vs 자동 생성 문서

## 대상 문서

- **수동 작성**: `CORE_FEATURES.md` (Claude Code가 src/index.ts 기반으로 수동 작성)
- **자동 생성**: `GENERATED_FEATURES.md` (`tsdoc-edge scan --group-by-category` 실행 결과)

---

## 비교 결과

### ✅ 자동 생성의 장점

1. **완전성 (Completeness)**
   - 수동: 26개 심볼 (선별적 큐레이션)
   - 자동: 131개 exported 심볼 (모든 공개 API 포함)
   - **자동 생성이 5배 더 완전함**

2. **정확성 (Accuracy)**
   - 수동: 파일 경로 추측, 라인 번호 없음
   - 자동: 실제 소스 코드에서 추출한 정확한 위치 정보
   - **자동 생성이 100% 정확함**

3. **최신성 (Freshness)**
   - 수동: 작성 시점에서만 정확
   - 자동: 매 실행마다 최신 코드베이스 반영
   - **자동 생성이 항상 최신 상태 유지**

4. **일관성 (Consistency)**
   - 수동: 섹션별로 상세 수준 차이 (어떤 건 bullet points, 어떤 건 간단 설명)
   - 자동: 모든 심볼에 동일한 포맷 적용
   - **자동 생성이 더 일관됨**

5. **효율성 (Efficiency)**
   - 수동: ~15분 소요 (분석 + 작성)
   - 자동: ~3초 소요 (scan 명령어)
   - **자동 생성이 300배 빠름**

### ⚠️ 자동 생성의 한계

1. **큐레이션 부족**
   - 모든 exported 심볼을 나열하므로, 중요도가 낮은 utility 함수들도 포함
   - 예: `isEmptyOrWhitespace`, `normalizeLineEndings` 등 5개 함수가 모두 Core Workflow에 포함됨

2. **맥락 설명 부족**
   - 수동: "파싱 → 검증 → 문서 생성" 같은 워크플로우 설명 포함
   - 자동: TSDoc summary만 나열, 전체 흐름 설명 없음

3. **부가 정보 부족**
   - 수동: "참조: src/analyzer/" 같은 간결한 표현
   - 자동: TSDoc에 없는 정보는 누락 (계약, 책임, 테스트 시나리오 등)

4. **카테고리 정확도**
   - 자동 분류가 경로 기반이라, 일부 잘못 분류될 수 있음
   - 예: Utility 함수가 Core Workflow로 분류

## 결론

### 자동 생성이 적합한 경우
1. ✅ API Reference 생성 (모든 공개 심볼 문서화)
2. ✅ 대규모 프로젝트 (수동 작성 불가능)
3. ✅ CI/CD 파이프라인 (자동 업데이트)
4. ✅ 정확한 위치 정보 필요
5. ✅ 빠른 프로토타이핑

### 수동 작성이 적합한 경우
1. ✅ 개요/튜토리얼 (선택과 집중)
2. ✅ 워크플로우 설명 (A → B → C 흐름)
3. ✅ 중요도 기반 큐레이션
4. ✅ 초심자 친화적 문서
5. ✅ 마케팅/홍보 자료

### 최적 전략: 하이브리드 접근

```bash
# 1. 자동으로 전체 API 문서 생성
tsdoc-edge scan --depth=2 --output=docs/API_REFERENCE.md

# 2. 카테고리별로 정리된 핵심 기능 문서 생성
tsdoc-edge scan --group-by-category --output=docs/CORE_FEATURES_AUTO.md

# 3. 수동으로 큐레이션된 개요 문서 작성 (CORE_FEATURES.md)
# - 자동 생성 문서를 참고하되, 핵심만 선별
# - 워크플로우 설명 추가
# - 예제와 맥락 추가
```

## 품질 개선 방향

자동 생성 문서의 품질을 높이려면:

1. **필터링 옵션 추가**
   ```bash
   tsdoc-edge scan --group-by-category --min-importance=important
   ```
   → utility 함수 제외, 핵심만 포함

2. **TSDoc 메타데이터 활용**
   - `@responsibility`, `@contract` 태그가 있으면 표시
   - `@testScenario` 있으면 테스트 커버리지 표시

3. **관계 시각화**
   ```
   TSDocEdge
   ├─ depends on → TSDocParser
   ├─ depends on → ConventionValidator
   └─ depends on → MarkdownGenerator
   ```

4. **사용 빈도 기반 정렬**
   - 가장 많이 사용되는 심볼부터 표시
